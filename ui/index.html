Open one of the two raw dialogs. While it is open, the page clock keeps counting, but the backend ticks and the call that asks the window its size stop. Close the dialog: what was held arrives in a burst, and the log below gets a "stalled" line. The plain invoke keeps answering, because its answer doesn't go through tao's queue. The dialog plugin's dialogs don't run a nested loop and stall nothing; neither does the 5 s sleep on a thread, the control. This happens on Linux; on Windows and macOS the same app is expected not to stall.
